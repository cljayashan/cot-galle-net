Unit 6 · Virtual Private Network (VPN)

6.3Tunnelling and encapsulation

In tunnelling, the original packet is encrypted and wrapped inside another packet with new outer IP addresses (the VPN endpoints). Routers on the Internet see only the outer header. At the far end the packet is decrypted and delivered to the private network.

Encapsulation step by step

  1. Your PC creates a normal private packet (for example to 10.0.0.50).
  2. The VPN software encrypts that packet.
  3. It wraps the result in a new outer packet addressed from your public IP (or VPN client address) to the VPN gateway's public IP.
  4. Internet routers forward using only the outer header. They cannot read the inner addresses or payload.
  5. The gateway decrypts, unwraps, and forwards the original packet onto the private LAN.

This wrapping is encapsulation (and the reverse is decapsulation). Protocols differ (IPsec ESP, WireGuard UDP payloads, OpenVPN TLS), but the idea is the same.

Common mistake: assuming VPN traffic is invisible. Observers still see that you are talking to a VPN server and how much data you send; they should not see the inner contents.

Remember

  • Inner packet = real conversation; outer packet = tunnel between VPN endpoints.
  • Encryption happens before the data crosses the untrusted network.
