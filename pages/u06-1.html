Unit 6 · Virtual Private Network (VPN)

6.1Concept

A Virtual Private Network creates an encrypted tunnel across an untrusted network (the Internet) so that remote users and sites can communicate as if on one private network. It provides:

  • Confidentiality: data is encrypted.
  • Integrity: data cannot be altered unnoticed.
  • Authentication: only authorised users or devices connect.

What a VPN does not do

It does not remove viruses, stop a user pasting a password into a fake site, or fix a misconfigured firewall behind the gateway. It protects the path. Combine it with patching, MFA and least privilege from Unit 8.

VPN and the CIA triad

A Virtual Private Network builds a protected path across a network you do not trust (usually the Internet):

  • Confidentiality: encryption stops eavesdroppers on café Wi-Fi or ISP links from reading the data.
  • Integrity: tampering with packets in transit is detected.
  • Authentication: only users or sites with valid credentials/keys join the tunnel.

After the tunnel is up, applications behave much as they would on the office LAN: you can open internal web apps, file shares or SSH hosts by their private addresses (depending on how the VPN is routed).

Everyday example: a teacher at home starts the school VPN client, authenticates, and then opens an internal marks system at 10.0.0.50 as if sitting in the staff room. Neighbours on the same home Wi-Fi see only encrypted VPN packets.

Remember

  • A VPN is an encrypted tunnel across an untrusted network.
  • It protects data in transit, not a malware-infected endpoint.
