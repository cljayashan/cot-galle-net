8.2.1Types of firewall

TypeHow it worksNotes
Packet-filteringChecks source/destination IP, port and protocol of each packetFast, simple; no knowledge of connection state
Stateful inspectionTracks connection state and allows replies to permitted outbound trafficStandard in routers and servers
Proxy / application gatewayActs as intermediary and inspects application dataDeep control, slower
Next-Generation Firewall (NGFW)Adds application awareness, intrusion prevention, user identity, TLS inspectionEnterprise networks
Web Application Firewall (WAF)Protects web apps from SQL injection, XSSIn front of web servers
Host-based vs network-basedRuns on one computer vs protects a whole networkUse both (defence in depth)

Placement

  • Border NGFW/firewall: between ISP and your LAN/DMZ.
  • Host firewall: on each server (UFW, firewalld, Windows Firewall).
  • WAF: only in front of web applications that need HTTP-aware protection.

Rules at the border do not replace host firewalls: an infected laptop inside the LAN can still attack a server unless the host filters that traffic too.

Which firewall type fits?

  • Packet filters are fast but cannot tell whether a packet belongs to a real conversation.
  • Stateful firewalls track connections: if you allow outbound HTTPS, the return packets are allowed automatically. Home routers and ufw/firewalld work this way.
  • Proxies terminate the session and rebuild it, inspecting content deeply (good for policy, costlier in latency).
  • NGFW add application identity ("block Facebook but allow HTTPS to the bank") and often IDS/IPS features.
  • WAF sit in front of web apps to catch SQL injection and XSS that network firewalls miss.
  • Use network and host firewalls together: the perimeter blocks the Internet; the host still protects itself if something bypasses the perimeter.

Remember

  • Stateful inspection is the baseline for modern networks.
  • Host + network firewalls = defence in depth.
