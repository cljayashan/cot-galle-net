8.4Digital signature

A digital signature proves who created a message (authentication), that it was not altered (integrity) and that the signer cannot deny it (non-repudiation).

Signing: the sender (1) computes a hash of the message, (2) encrypts the hash with the sender's private key; the result is the signature, sent with the message.

Verifying: the receiver (1) hashes the received message, (2) decrypts the signature with the sender's public key, and (3) compares the two hashes. If they match, the message is authentic and unchanged.

Note the reversal: encryption for secrecy uses the receiver's public key; a signature uses the sender's private key.

TaskKey used
Encrypt a message for secrecyreceiver's public key
Decrypt the messagereceiver's private key
Sign a messagesender's private key
Verify a signaturesender's public key

"Encrypting the hash with the private key" describes RSA signatures. Other algorithms, such as ECDSA and Ed25519, calculate the signature differently, but the rule is the same: sign with the private key, verify with the public key.
