SSH example:

Terminal
ssh user@192.168.1.10
ssh-keygen -t ed25519                 # create a key pair on your PC
ssh-copy-id user@192.168.1.10         # install your public key on the server
scp report.pdf user@192.168.1.10:/home/user/

Good practice: disable password login once keys work (PasswordAuthentication no in /etc/ssh/sshd_config), use least-privilege accounts, and log all administrative sessions.

SSH keys in one paragraph

You create a key pair on your PC (ssh-keygen). The public key is copied to the server (authorized_keys). The private key stays on your PC and never travels. Later logins prove you hold the private key. Once that works, disable password authentication so attackers cannot guess passwords on port 22.

Tip: do not publish RDP (3389) or SSH (22) straight to the whole Internet. Use a VPN (Unit 6), restrict source IPs, or jump through a bastion host.

Remember

  • Prefer encrypted, key-based, least-privilege remote access.
  • Out-of-band management saves you when the OS network stack is broken.
  • Telnet is obsolete for administration.
