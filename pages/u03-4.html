Unit 3 · Network Devices and Protocols

3.4Reference models

A reference model divides communication into layers so that vendors can build interoperable products and engineers can troubleshoot one layer at a time.

Analogy: sending data is like posting a letter. You write the letter (application), put it in an envelope with the address (network layer), the post office sorts it (routers) and a van carries it (physical). The receiver reverses every step.

Why layers?

Networking is a very big problem. Layering splits it into smaller jobs, each handled by one layer, which only needs to talk to the layer directly above and below it. This brings three benefits:

  • Interoperability: a web browser from one company works over a Wi-Fi card from another and a router from a third, because each follows the standard for its own layer.
  • Independent change: you can replace Wi-Fi with Ethernet (lower layers) without changing the browser (top layer).
  • Troubleshooting: engineers can test one layer at a time. "The cable is fine, the IP address is fine, so the problem must be DNS" is layered thinking (see 9.1).

Two models

  • The OSI model (7 layers) is a reference model used for teaching and troubleshooting. Its layer numbers are used every day: people say "Layer 2 switch" or "a Layer 7 firewall".
  • The TCP/IP model (4 layers) describes the protocols the Internet actually uses.

Key words in this topic

  • OSI 7-layer model: teaching and troubleshooting map.
  • TCP/IP model: the model the Internet actually implements.
  • Encapsulation: data gains headers (and sometimes trailers) as it moves down the stack.
