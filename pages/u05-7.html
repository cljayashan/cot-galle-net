5.7Ports

An IP address identifies a host; a port number (16 bits, 0-65535) identifies the application or service on that host. A socket is IP address plus port (for example 192.168.1.10:443). Ports can be TCP or UDP.

Ports complete the address

An IP address finds the computer; a port finds the program. Together they form a socket (192.168.1.10:443). Servers listen on well-known ports; clients pick temporary ephemeral ports for their side of the conversation.

Security rule of thumb

List what is listening (ss -tulpn or netstat -ano). For each port ask: "Do we need this?" If not, stop the service or block it on the firewall. Attackers scan for unexpected open ports (Telnet, old database ports, remote desktop) as easy entry points.

If you seeThink
Port 22 open to worldRestrict or put behind VPN
Port 3306 on public IPDatabase should usually be internal only
Many unknown listenersInventory services; disable unused ones

Remember

  • Well-known 0–1023, registered 1024–49151, ephemeral above that.
  • Open only needed ports; verify with ss/netstat/nmap on systems you own.

Checking and securing ports

Terminal
sudo ss -tulpn          # Linux: list listening ports and their programs
netstat -ano            # Windows: connections with process IDs
nmap -sT 192.168.1.10   # scan a server from another machine (only your own!)

Security rule: open only the ports a server needs; close or firewall all others. Unused open ports are attack entry points. Port forwarding on a router maps a public port to an internal server port (for example public 8080 to 192.168.1.10:80).
