8.2.3Configuring firewalls: UFW, Windows and iptables

On this page
  1. UFW on Ubuntu
  2. Windows Defender Firewall
  3. iptables on Linux

UFW on Ubuntu

Terminal
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp          # SSH
sudo ufw allow 80/tcp          # HTTP
sudo ufw allow 443/tcp         # HTTPS
sudo ufw allow from 192.168.1.0/24 to any port 3306   # database only from LAN
sudo ufw enable
sudo ufw status verbose

Windows Defender Firewall

Open Windows Defender Firewall with Advanced Security; create an Inbound Rule > Port > TCP 443 > Allow the connection > choose profiles (Domain/Private/Public) > name the rule. Use New-NetFirewallRule in PowerShell for automation.

iptables on Linux

Terminal
sudo iptables -A INPUT -i lo -j ACCEPT                                        # local traffic
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT   # replies
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT                            # SSH
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT                            # HTTP
sudo iptables -A INPUT -j DROP                                                # everything else
sudo iptables -L -n -v --line-numbers

Do not lock yourself out. A rule set that only allows port 80 and then drops everything also blocks SSH, local (loopback) traffic and the replies to the server's own connections, so a remote server becomes unreachable. Allow loopback, established connections and SSH first. iptables rules are lost at reboot unless saved (for example with the iptables-persistent package).

Commands mean policy

On Ubuntu UFW:

Shell
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80,443/tcp
sudo ufw enable
sudo ufw status verbose

This denies unsolicited inbound traffic, keeps outbound open, and permits SSH and web. Always allow your admin access method before enabling a firewall on a remote VM, or you can lock yourself out.

Windows Defender Firewall uses inbound/outbound rules per profile (Domain/Private/Public). iptables/nftables are the lower-level Linux tools UFW wraps.

Common mistake: enabling UFW with no allow rule for SSH while connected only over SSH — you lose access until console recovery.

Remember

  • Set defaults, allow needed ports, then enable.
  • Test from another machine; keep a console/out-of-band path.
