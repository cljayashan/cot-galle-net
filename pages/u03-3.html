3.3Network protocols

A protocol is a set of rules that defines the format, order and actions for communication. Protocols are grouped into a protocol suite; the Internet uses the TCP/IP suite.

Ports: how a protocol finds the right application

A server can run a web server, a mail server and SSH at the same time, all on one IP address. The port number in each segment tells the operating system which application the data is for: 443 for HTTPS, 22 for SSH, and so on. The table above lists the standard ports. They are explained further in 5.7.

Secure and insecure versions

Several older protocols send everything, including passwords, as plain text: Telnet, FTP, HTTP, POP3 and IMAP without TLS. Each has a secure replacement: SSH, SFTP, HTTPS, and POP3/IMAP over TLS (ports 995 and 993). Always use the secure version, especially across the Internet or on Wi-Fi.

Protocols used every day

  • HTTP/HTTPS: fetches web pages and powers most apps. HTTPS adds TLS encryption (see 8.5).
  • DNS: turns names into addresses before almost every connection (see Unit 7).
  • DHCP: gives each device its address when it joins the network.
  • SMTP, IMAP and POP3: SMTP sends mail (and passes it between mail servers); IMAP and POP3 let a mail program collect it. IMAP keeps mail on the server so that it stays in step on every device; POP3 usually downloads and removes it.
  • ICMP: carries error and test messages. ping and traceroute use it.
  • ARP: finds the MAC address that belongs to an IP address on the local network (see 4.1).

Key words in this topic

  • TCP: reliable, connection-oriented, ordered delivery.
  • UDP: lightweight, no connection setup, no guaranteed delivery.
  • DHCP: automatic IPv4 host configuration (DORA: Discover, Offer, Request, Acknowledge).
