3.3.2DHCP and the DORA process

A client with no address broadcasts Discover; the server replies Offer; the client sends Request; the server sends Acknowledgement carrying the IP address, mask, gateway, DNS server and lease time.

Why DHCP?

Configuring every device by hand is slow and error-prone: a single mistyped address or a duplicated address stops a device working. With DHCP (Dynamic Host Configuration Protocol), a device joining the network is configured automatically in about a second, and the administrator controls all the settings from one place.

The four messages in detail

  1. Discover: the new client has no IP address and does not know where the server is, so it broadcasts to the whole LAN: "Is there a DHCP server?" It uses source address 0.0.0.0 and destination 255.255.255.255, from UDP port 68 to port 67.
  2. Offer: a DHCP server replies with an offer: "You can have 192.168.1.105."
  3. Request: the client broadcasts that it accepts that offer. It is sent as a broadcast so that, if several servers made offers, the others know they were not chosen.
  4. Acknowledge: the chosen server confirms, and sends the full settings: IP address, subnet mask, default gateway, DNS servers and lease time.

Leases

The address is leased, not given for ever. When half the lease time has passed, the client asks the same server to renew it. If the device leaves the network, its lease eventually expires and the address goes back into the pool for someone else. Typical lease times are 8 hours for guest Wi-Fi and 8 days for office PCs.

DHCP across routers

Routers do not forward broadcasts, so a Discover never leaves its own subnet. If the DHCP server is on a different subnet (common when one central server serves many VLANs), the router on each subnet is configured as a DHCP relay (on Cisco, the ip helper-address command). It picks up the broadcast and forwards it as a normal unicast message to the server.

When DHCP fails

If no server answers, a Windows client gives itself an APIPA address in 169.254.0.0/16. It can only talk to other APIPA devices, not to the Internet. A 169.254 address is therefore a clear sign of a DHCP problem (see 9.5). Another risk is a rogue DHCP server: a home router plugged into the office network hands out wrong addresses. Managed switches can block this with DHCP snooping.

Remember

  • DHCP gives out IP address, mask, gateway and DNS automatically through Discover, Offer, Request, Acknowledge.
  • Addresses are leased; reservations always give a device the same address.
  • A relay (ip helper-address) is needed when the server is on another subnet.
