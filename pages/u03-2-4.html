3.2.4VLANs and trunk ports

A VLAN divides one physical switch into several logical networks (for example, Staff and Students), improving security and reducing broadcast traffic.

Cisco IOS CLI
SW1(config)# vlan 10
SW1(config-vlan)# name STAFF
SW1(config-vlan)# exit
SW1(config)# vlan 20
SW1(config-vlan)# name STUDENTS
SW1(config-vlan)# exit
SW1(config)# interface fastEthernet 0/1
SW1(config-if)# switchport mode access
SW1(config-if)# switchport access vlan 10
SW1(config-if)# exit
SW1(config)# interface fastEthernet 0/24
SW1(config-if)# switchport mode trunk
SW1(config-if)# end

Ports that carry several VLANs between switches are trunk ports (IEEE 802.1Q tagging).

Why use VLANs?

Without VLANs, every device connected to the switches is in one large network: one broadcast domain. That causes three problems:

  • Security: student PCs can reach staff PCs and servers directly.
  • Broadcast traffic: every broadcast (such as ARP and DHCP requests) reaches every device, which wastes bandwidth and CPU as the network grows.
  • Management: grouping users by department means rewiring whenever someone moves.

With VLANs, each group gets its own logical network, even on shared switches. Moving a user to another department is a one-line change on the switch port.

Access ports and trunk ports

  • An access port belongs to exactly one VLAN and connects an end device such as a PC or printer. The PC does not know that VLANs exist; it sends and receives normal frames.
  • A trunk port carries traffic for many VLANs over one link, usually between switches, or from a switch to a router. To keep the VLANs apart, each frame is given a small 802.1Q tag containing its VLAN number. The receiving switch reads the tag, removes it, and sends the frame only to ports in that VLAN.

One VLAN on a trunk, the native VLAN (VLAN 1 by default), is sent untagged. For security, many administrators change the native VLAN to an unused VLAN number.

VLANs and IP subnets

Each VLAN is normally given its own IP subnet, for example VLAN 10 STAFF = 192.168.10.0/24 and VLAN 20 STUDENTS = 192.168.20.0/24. Devices in different VLANs cannot talk to each other unless a Layer 3 device routes between them. This is done either by a router with one trunk link divided into sub-interfaces (router-on-a-stick), or by a Layer 3 switch. That router is also where you can apply rules, for example "students may reach the web server but not the staff file server".

Checking VLANs

show vlan brief lists each VLAN and its access ports. Trunk ports are not listed there; use show interfaces trunk to see which ports are trunks and which VLANs they carry.

Common mistakes: forgetting switchport mode access (the port may then negotiate to become a trunk); putting a PC in the wrong VLAN, so it gets no address or the wrong one; a trunk that does not allow a VLAN, so devices on another switch cannot reach it.

Remember

  • A VLAN splits one switch into separate logical networks (separate broadcast domains).
  • Access ports carry one VLAN; trunk ports carry many, using 802.1Q tags.
  • Each VLAN is its own subnet, and a router or Layer 3 switch is needed between them.
