Unit 8 · Network Security

8.2.2Rule design, DMZ and ACLs

Firewall rule design

  • Rules are checked top to bottom; the first match wins.
  • Apply default deny: block everything not explicitly allowed.
  • Allow only required services (for example inbound 80, 443; SSH only from the admin network).
  • Document each rule and review regularly.

DMZ (demilitarised zone): a separate network segment for public-facing servers (web, mail) so that if one is compromised the internal LAN is still protected by a second firewall.

Access control lists (ACLs)

Routers and switches use ACLs to permit or deny packets; for example, a standard ACL filters by source IP only, an extended ACL by source, destination, protocol and port.

Writing rules that stay understandable

Good policy starts with default deny inbound on servers: only open the ports each role needs (80/443 for web, 53 for DNS, and so on). Outbound rules may be looser on clients but tighter on hardened servers.

Order matters on many platforms: first match wins. Put specific denies/allows before general ones, and document why each rule exists.

DMZ idea

Public web servers belong in a DMZ VLAN/segment that can talk to the Internet on limited ports, and may talk to internal databases only on the exact port required — not full LAN access. If the web server is compromised, the blast radius is smaller.

Everyday example: allow Internet → DMZ:443; allow DMZ → internal DB:3306 from web server IP only; deny DMZ → internal LAN otherwise.

Remember

  • Default deny; least ports; document rules.
  • DMZ separates public servers from internal trust.
