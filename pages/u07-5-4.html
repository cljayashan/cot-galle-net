Unit 7 · Domain Name System (DNS)

7.5.4DNS attacks and protection

Cache poisoning/spoofing, DNS amplification DDoS, tunnelling and hijacking. Protect with DNSSEC, restricted recursion (do not run an open resolver), rate limiting, patching, firewall rules and registrar account security (strong password and multi-factor authentication).

Hardening one-liners

  • Recursion: allow only LAN nets, not any.
  • Zone transfers: allow only listed secondary IPs.
  • Keep BIND/Windows DNS patched.
  • Monitor for sudden spikes in query rate (amplification abuse).
  • Registrar: MFA + lock so NS records cannot be hijacked quietly.

Attacks and simple defences

AttackIdeaDefence
Cache poisoningFeed a resolver a fake answerDNSSEC validation; keep software patched; limit who may query
Amplification DDoSSmall spoofed query → large reply to victimDisable open recursion; rate-limit; filter spoofing
Domain hijackingSteal registrar login, change NSMFA on registrar; registrar lock
DNS tunnellingHide data inside DNS queriesMonitor odd DNS patterns; restrict outbound DNS

An open resolver (anyone on the Internet may recurse through you) is a gift to attackers. Authoritative servers should answer for their zones; recursion should be limited to trusted client networks.

Remember

  • Patch, restrict recursion, protect registrar accounts, consider DNSSEC.
  • DNS security is both server configuration and account hygiene.
