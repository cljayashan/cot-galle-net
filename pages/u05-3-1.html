5.3.1Selecting a server

Consider: workload (users, transactions, data volume), CPU cores, RAM, storage (SSD vs HDD, RAID level), network bandwidth, availability (redundant power supplies, clustering, backups), security and compliance, scalability, budget (purchase plus running cost), support and warranty, and skills available.

Basic RAID levels: RAID 0 (striping, speed, no protection), RAID 1 (mirroring), RAID 5 (striping with parity, survives one disk failure), RAID 6 (two disk failures), RAID 10 (mirror plus stripe).

RAID is not a backup. It keeps a server running when a disk fails, but deleted files, ransomware and fire affect every disk at once. Keep separate backups.

Worked example: a school needs a web server for 500 students and a file server for 50 staff. A virtual machine on one on-premises host or a small cloud VPS (2 vCPU, 4 GB RAM) is enough for the web server; the file server needs mirrored disks and daily backup. A dedicated server would be wasteful.

Capacity planning questions

  1. How many simultaneous users and what do they do (browse, edit big files, run a shop)?
  2. How much storage now, and in two years?
  3. What happens if this server is down for an hour? a day?
  4. Who will patch and monitor it, and with which skills?

RAID is not backup. Ransomware, accidental deletion and site disasters affect every disk in the array. Keep separate, tested backups (ideally off-site).

Remember

  • Match CPU, RAM, disk and network to the workload; plan for growth.
  • RAID keeps the server running after a disk fault; backups recover from data loss.
