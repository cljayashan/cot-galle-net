Unit 3 · Network Devices and Protocols

3.2.1Planning checklist

  1. Draw the network diagram and list the devices and cables needed.
  2. Plan IP addressing (see Unit 4) and VLANs if needed.
  3. Mount equipment, label cables, connect power and uplinks.
  4. Connect to the device console (serial cable and terminal program such as PuTTY at 9600 baud) for first-time setup.
  5. Apply configuration, test, save, and document.

Planning: why it matters

A network that is planned on paper first is quicker to install, has fewer faults and is much easier to troubleshoot later. For each device, write down its name, location, management IP address, the purpose of each port, and its VLANs. Draw two diagrams: a physical diagram (where devices are and how the cables run) and a logical diagram (subnets, VLANs and IP addresses).

A consistent naming scheme, such as building, floor and device (B1-F2-SW1), lets anyone find a device from its name alone.

First access through the console

A new switch or router has no IP address, so you cannot reach it over the network. Instead you connect to its console port:

  1. Connect a console cable from your PC (a USB-to-serial adapter, or a USB console cable if the device has a USB console port) to the console port.
  2. Open a terminal program such as PuTTY, choose Serial, select the COM port shown in Device Manager, and set 9600 baud, 8 data bits, no parity, 1 stop bit, no flow control.
  3. Press Enter. You should see the device's prompt, such as Switch>.

After the device has an IP address and SSH is set up (see 3.2.2), you can manage it from anywhere on the network, and only need the console again for recovery.

Installing the hardware

  • Mount devices in a rack with enough space for air to flow, and connect them to a UPS.
  • Use patch panels so that the fixed cabling is never plugged directly into switches.
  • Label both ends of every cable, and record which switch port each wall socket uses.
  • Keep power and data cables apart to reduce interference.

After configuring: test, save and document

Test every function you configured (ping between devices, test SSH, check VLAN membership). Save the configuration on the device and keep a backup copy of it on a server. Update the documentation with any change. Good documentation turns a two-hour fault into a ten-minute fix.

Remember

  • Plan first: diagrams, names, IP addresses and VLANs.
  • First-time setup uses the console port at 9600 baud.
  • Test, save, back up and document every change.
