Unit 5 · Server Installation, Setting Up and Configuration

5.4.3Windows Server first tasks

Use Server Manager to rename the computer, set a static IP (Network Connections), run Windows Update, and add roles with Add Roles and Features (or PowerShell: Install-WindowsFeature DNS -IncludeManagementTools).

PowerShell
Rename-Computer -NewName SRV1 -Restart
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 192.168.1.20 -PrefixLength 24 -DefaultGateway 192.168.1.1
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 192.168.1.10
Install-WindowsFeature DNS, DHCP -IncludeManagementTools
Get-WindowsFeature | Where-Object Installed

These PowerShell commands do the same jobs as Server Manager. Change the interface name (Get-NetAdapter lists them) and the addresses to suit your network.

Why these first tasks come before roles

Adding DNS or DHCP on a machine that still has a random hostname, a DHCP-assigned address and unpatched services creates moving targets: clients cache the wrong IP, certificates disagree with the name, and attackers find known bugs. Finish identity (name), addressing (static IP), and updates first; then add roles; then harden the firewall to match those roles only.

Everyday example: a lab installs DHCP before setting a static IP on the server itself. After a reboot the server gets a new address from another DHCP box, and every client that was pointed at the old address stops resolving names.

First hour on Windows Server

  1. Rename the computer and reboot (Rename-Computer).
  2. Set a static IP, mask, gateway and DNS (New-NetIPAddress, Set-DnsClientServerAddress). Check the interface name with Get-NetAdapter.
  3. Run Windows Update before adding public roles.
  4. Add only needed roles (DNS, DHCP, AD DS, File Server…) with Server Manager or Install-WindowsFeature.
  5. Enable the firewall appropriately and create a standard admin workflow (separate accounts, not shared passwords).

Common mistake: leaving a server on DHCP. If its address changes, every client, DNS record and firewall rule that pointed at the old IP breaks.

Remember

  • Same goals as Linux: identity, addressing, updates, roles, firewall, documentation.
  • PowerShell can do everything Server Manager can, and is easier to repeat.
